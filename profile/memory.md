## 源码阅读第二季：56 篇，品类扩张

上一季是「同一种读法复制到 9 个 AI 项目」；这一季是**换品类**。5 个新项目，读法没变，样本空间变了：

| 项目 | 篇数 | 它是什么 | 最值得看的东西 |
|------|------|----------|----------------|
| **REA** | 15 | 本地逆向工程工作台，统一 Ghidra/IDA/Hopper/JEB/JADX，CLI + MCP | 23 万行 TypeScript 靠 131 行检查器守住依赖方向；`AGENTS.md` 里的每条约定都能指到一个会失败的脚本 |
| **AI Job Search** | 11 | 把 Claude Code 当应用框架的求职工作流 | 「代码是 Markdown，运行时是 LLM」；招聘启事是不可信输入；有唯一正确答案的活儿从模型手里拿走 |
| **free-stockdb** | 10 | 本地 A 股数据引擎 | LevelDB + C++ 更新器/服务器 + Python SDK + Excel/HTML/MCP 五个薄入口，共用一套 key 协议 |
| **Cindy** | 10 | 开源 AI Agent 客户端 | Electron 桌面 + 手机远程控制；Claude Code/Codex/Pi 三引擎统一；权限档位、插件沙箱、`AGENTS.md` + guard + DCO 治理 |
| **Medusa** | 10 | 开源电商后端 | 34 个模块拆开；module link 代替外键，query graph 跨模块读，workflow 补偿事务跨模块写 |

加上之前的项目，`source-read/` 现在是 **19 个项目、142 篇**。读法仍然是那套：一句话概括 → 架构图 → 关键代码 → 好在哪/骨架代码 → 小结。但选材明显从「AI 框架」扩到了**业务系统、逆向工程、金融数据、Agent 客户端**。

最值得记住的两条洞察：

1. **约定要装成门禁，不能只写在墙上。** REA 的 `AGENTS.md` 不是文档，是索引：每条不变量都映射到一个脚本、一个 CI 接线点。Cindy 也一样——`docs/*-rules` 是正文，`scripts/check-*` 是门禁。
2. **有唯一正确答案的事，不要让 LLM 做。** AI Job Search 把去重 key、日期计算、PDF 版面检查从 prompt 移到 Python；REA 把依赖方向、生成物一致性、错误 schema 校验移到脚本。这是「AI 是运行时」的工程化表达。

## 企业应用架构：20 篇，规模决定架构

9/24 一天写完的系列，从「业务逻辑写在哪」开始，一路推到 DDD、CQRS/事件溯源，最后用一篇反方收尾。

它的价值不在模式本身，而在**算账**：

- 同一个下单场景，事务脚本 85 行，数据映射器 150 行，服务层 174 行；
- 18 篇文章讲了 13 类模式，一个 8~10 张表的管理后台只需要 2 类；
- 「全套 DDD + 六边形」在这个场景里不是更专业，是**认知负担和代码量同时翻倍**。

总纲用「街边小馆 vs 米其林后厨」把整条主线说清楚了：**不是米其林更先进，是规模决定你该怎么分工。** 这和你之前写的「项目结构是发布单元的投影」是同一个思路——先看规模、边界、发布单元，再决定要不要上模式。

## C++ 与图形：23 篇，向下走

这是 10-11 月最大的新方向。

**C++ 20 篇**：基础语法 4 篇、OOP 6 篇，再加 RAII、移动语义、智能指针、异常安全、编译链接、模板与 Concepts、lambda、STL 迭代器、并发、Unix Domain Socket。不是「语法速查」，是沿着「资源归谁管、对象什么时候销毁、代码在编译期还是运行期决定」这条线写下来的。示例用 C++23 实际编译运行，CMake/CTest 的构建和测试输出都在文章里。

**图形 3 篇**：同一个目标——在窗口里画一个三角形——分别走 Cocoa + Metal、Win32 + D3D11、XCB + Vulkan。窗口创建、GPU 初始化、shader、交换链、渲染循环、同步全写出来。Metal 和 Vulkan 的 demo 实际跑通，D3D11 在 macOS 上用 mingw-w64 交叉编译，文章明确标注了运行时需要 Windows。**「跑通才算」在这里体现得最彻底。**

连起来看，这不是「又学了一门语言」，是**从应用层往系统层下探**：编译链接、ABI、进程间通信、GPU 命令提交。你之前补的是分布式系统（服务之间怎么协作），现在补的是单机系统（进程、内存、文件描述符、GPU）。

## 工程规范：从写代码到写流程

11 月的另一条线，是把「工程本身」当系统来设计：

- **项目结构 9 篇（含总纲）**：Go、Python、TypeScript、Rust、Java、C#/.NET、C++ 七种语言 + 反模式 + 总纲。核心论点一句话：**结构是发布单元的投影**。先确定 module/crate/package/assembly 的边界，再决定目录。
- **项目文档清单**：核心五个半（README、LICENSE、.gitignore、CHANGELOG、CONTRIBUTING、CoC）、ADR、runbook、数据字典、术语表、文档治理。核心观点是「文档是读者的接口」，不是文件清单。
- **Web UI 测试**：Playwright / Cypress / Selenium / WebdriverIO / Puppeteer 的层级和选型，组件测试、E2E、视觉回归、可访问性分开看。实际跑了两条 Playwright 用例。
- **Code Review 工具**：机械检查 → 深度静态分析 → 流程规则 → AI 初筛 → 人工终审的五层流水线；Open Code Review、PR-Agent、Kodus、reviewdog、Danger、SonarQube、Semgrep、CodeQL 各自的位置。
- **七道闸门**：brainstorming → worktree → plan → subagent/inline → TDD → code review → finishing。每道闸门只做一件事：把一种模糊的东西变成可检查的产物。

这四个方向 + 七道闸门，加上之前的 source-read 规范、脱敏约定、备份脚本，构成了一套**个人工程规范体系**。你不再只是「写代码的人」，也在设计「代码怎么被写、被检查、被交付」。

## AI 协作：从用到管

AI 这条线没有断，只是关注点变了：

- **七道闸门**：把 AI 辅助开发拆成可检查的检查点，先问清楚再让 AI 写，TDD 和 review 是硬门禁。
- **T3 Code**：不做新 Agent，做**编码 Agent 的控制面**——桌面/Web/手机连同一个 server，线程、worktree、审批、checkpoint 统一管理。0.1.x 就拿到 6 万 star，概念对了。
- **Cindy**：开源 Agent 客户端，桌面执行 + 手机远程控制，把 Claude Code/Codex/Pi 统一到一个会话界面。
- **AI Job Search**：把 Claude Code 当应用框架，Markdown 是代码，LLM 是运行时；信任边界、确定性脚本、验证回路都按应用来设计。

共同点：**你关心的不再是「哪个模型更强」，而是「Agent 在什么边界内工作、怎么被审批、怎么被验证、怎么跨设备接管」。** 从 evaluator 变成了 workflow designer。

## 金融终端：最后一公里

10 月的 QMT/EasyTHS 两篇，补的是量化链路里最脏的一段：**当券商只给你一个封闭终端，策略代码怎么下单。**

- **xtquant_big_convert**：在大 QMT 进程里跑一个普通策略，由它启动 RPC 服务，把 `ContextInfo` / `passorder` 暴露给外部；同时提供 `xtquant` 兼容层。不是注入，是在宿主里开一个服务窗口。
- **EasyTHS**：用 pywinauto 操作已登录的同花顺 `xiadan.exe`，对外提供 REST API、Python SDK、MCP 和 Web 控制台。没有注入、没有 hook，就是「程序点终端」。
- **free-stockdb**：把全市场数据同步到本地 LevelDB，用 C++ 服务 + Python SDK + MCP 暴露出去。

三个项目连起来，是一条完整的「数据 → 策略 → 执行」边缘链路。你对这类项目的判断也很清楚：不把它们当高频系统，不当官方 API 的替代品，只当**没有官方接口时的最后一公里执行器**。

## 最近的变化

### 变化一：补基础的方向，从分布式转向系统底层

7-9 月补的是分布式系统、Kafka、TCP/IP——**服务之间怎么协作**。10-11 月补的是 C++、编译链接、UDS、GPU——**单机系统怎么运转**。前者让你能设计系统，后者让你知道系统底下发生了什么。

### 变化二：源码阅读从「产线」变成「品类组合」

上一季的成就感来自「同一套读法复制了 9 个项目」。这一季的重点不是数量，是**换品类**：电商、逆向、金融数据、Agent 客户端、Claude Code 应用。读法稳定之后，选材变成了新的变量。

### 变化三：从「用 AI」到「设计 AI 协作流程」

6 月你在测绘 AI 工具，7-9 月在拆 Agent 框架，11 月开始设计七道闸门、看 T3 Code 的控制面、读 Cindy 的权限模型。**从「AI 能做什么」转向「AI 应该在什么边界内做」。**

### 变化四：从「写技术」到「写工程规范」

项目结构、文档、测试、Code Review、七道闸门——这些不是新技术，是**让别人（和未来的自己）能接手的工作**。你开始把「怎么协作」本身当成一个需要设计的系统。

### 变化五：验证标准升级

C++ 示例实际编译，Metal/Vulkan 实际渲染，D3D11 交叉编译，Playwright 实际跑，文档检查实际跑 lint/契约/链接，还做负向测试。**「看起来对」越来越不算数，「跑过」才算。**

### 变化六：产出节奏仍然是批量提交

9 月 21 次、10 月 9 次、11 月 16 次提交。9/24 一天提交 6 次完成企业架构 20 篇，11/20 一天提交 5 次完成源码阅读、项目结构、测试/Review/文档。**产出没降，粒度越来越粗。**

## 结语

9 月的你是在给知识体系打地基；11 月的你，是在地基上同时起三栋楼：**业务架构、系统底层、工程流程**。

半年前的关键词是「扩张 + 工艺」，三个月前是「批量提取 + 补基础」，现在是「**架构判断 + 向下验证 + 流程工程化**」。

你不再只问「这个东西怎么用」，也不只问「它为什么这样设计」，而是开始问：

- 这个系统有多大，值得上这套模式吗？
- 这个结论跑过吗，能复现吗？
- 这个流程能让别人接手吗，还是只在我脑子里？
