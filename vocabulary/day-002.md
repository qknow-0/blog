# Day 002 — 2026-05-18

## 1. Sharding（分片）

将大型数据库水平拆分为多个独立实例，每个实例存储一部分数据。分片键的选择决定数据分布均匀度——选错了会出现热点分片。

## 2. Sidecar Pattern（边车模式）

将辅助功能（日志采集、服务发现、配置刷新）作为独立进程部署在主应用旁边，共享网络和存储。K8s Pod 里的 sidecar 容器和 Envoy proxy 是典型实现。

## 3. Exponential Backoff（指数退避）

失败重试时每次等待时间翻倍（1s → 2s → 4s → 8s），避免瞬时故障演变成雪崩。AWS SDK、gRPC 客户端都内置了指数退避重试。

## 4. Thundering Herd（惊群效应）

大量进程/线程同时等待一个事件，事件触发时全部被唤醒争抢，但只有一个能处理，其余白跑。缓存过期瞬间大量请求同时回源是最常见的惊群场景。

## 5. Fan-out / Fan-in（扇出 / 扇入）

- **Fan-out**：一个任务拆成多个子任务并行执行
- **Fan-in**：等待所有子任务完成后汇总结果  
Go 的 goroutine + channel、Python 的 `asyncio.gather()` 都是扇入扇出模型。

## 6. Hotspot（热点）

系统中被高频访问的部分——热点数据（某条缓存 key）、热点分片（某个 DB shard）、热点函数（某个 API）。优化的第一目标是消除或隔离热点。

## 7. Lazy Evaluation（惰性求值）

表达式在真正需要结果时才计算，而非定义时立即计算。Python 的 generator（`yield`）、Spark 的 transformations 直到 action 才执行都是惰性求值。

## 8. Checkpointing（检查点）

将系统当前状态快照保存到持久存储，崩溃后从检查点恢复而非从头开始。Flink/Spark 的容错机制、长时间训练 ML 模型的断点续训都依赖检查点。

## 9. Semantic Versioning（语义化版本）

`MAJOR.MINOR.PATCH` 格式：不兼容 API 改动加 MAJOR、向下兼容新增功能加 MINOR、向下兼容 bug 修复加 PATCH。`^1.2.3` 表示接受 `>=1.2.3 <2.0.0`。

## 10. Graceful Degradation（优雅降级）

当部分功能不可用时，核心功能继续运行而非整个系统崩溃。比如推荐服务挂了，首页展示默认热门内容而不是空白页——用户至少还能用。
