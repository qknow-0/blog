# Day 003 — 2026-05-24

## 1. Orthogonal /ɔːrˈθɒɡənəl/（正交）

两个系统或组件互相独立，改变一个不影响另一个。正交设计减少耦合——UI 层改动不影响业务逻辑层是好的正交，改一个 API 参数导致前端全崩就不是。

## 2. Deterministic /dɪˌtɜːrmɪˈnɪstɪk/（确定性的）

给定相同输入始终产生相同输出。纯函数是确定性的（`add(1,2)` 永远返回 3），依赖当前时间或随机数的函数不是。AI Agent 偏好确定性接口因为结果可复现。

## 3. Reconciliation /ˌrekənsɪliˈeɪʃən/（协调/调和）

将两个可能不一致的状态同步为一致状态的过程。React 的 Virtual DOM diff 被称为 reconciliation——计算新旧 UI 树的差异然后最小化 DOM 操作。数据库主从同步也是 reconciliation。

## 4. Observability /əbˌzɜːrvəˈbɪləti/（可观测性）

通过外部输出推断系统内部状态的能力。三大支柱：Logs（日志）、Metrics（指标）、Traces（链路追踪）。高可观测系统出问题时不需要 SSH 进去看。

## 5. Memoization /ˌmeməraɪˈzeɪʃən/（记忆化）

缓存函数调用结果，相同输入下次直接返回缓存值而不重新计算。`functools.lru_cache` 是 Python 内置的记忆化装饰器。递归 Fibonacci 从 O(2^n) 降到 O(n) 靠的就是这个。

## 6. Stale /steɪl/（过时/陈旧）

缓存的数据已不再反映数据源的当前状态。stale-while-revalidate 策略：先返回可能过时的缓存数据，同时异步刷新——用户体验（快）和准确性（最终一致）兼得。

## 7. Idempotency Key /ˌaɪdɪmˈpoʊtənsi kiː/（幂等键）

客户端生成唯一标识符随请求发送，服务端用它去重——同一请求发多次只执行一次。Stripe 的支付 API 大量使用幂等键防止用户被重复扣款。`PUT /order/123` 天然幂等，`POST /order` 需要幂等键辅助。

## 8. Compaction /kəmˈpækʃən/（压实/压缩）

将多个小文件或数据分片合并为更大更少的文件，减少碎片提升查询性能。Kafka 的 log compaction 保留每个 key 最新值丢弃旧版本，RocksDB/LevelDB 通过后台 compaction 维持读性能。

## 9. Lease /liːs/（租约）

分布式系统中授予某节点在有限时间内对资源的独占访问权。租约到期自动释放，防止节点崩溃后永久占锁。etcd 的 leader lease、分布式锁的红锁算法都基于这个机制。

## 10. Delta /ˈdeltə/（增量/差异）

两个版本之间的差异。Delta 编码只存储变化部分而非完整副本——Git 的每个 commit 本质是 delta，rsync 通过 delta 传输只同步文件的变化块。增量比全量快一个数量级。
